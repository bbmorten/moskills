# Assessment: Open WebUI v0.11.0 → v0.11.1 for aimo

Date: 2026-08-26. Release published 2026-08-25 (462 commits over v0.11.0).
Method: release notes + the full compare-API file diff were cross-checked
against the integration-touchpoint register; every high/medium intersection was
then verified by fetching the named backend file at BOTH tags from
raw.githubusercontent.com and diffing — 14 risks verified at source, plus 6 low
risks assessed from the diff alone. Point-in-time: statements below describe
the two tags as of this date.

## Verdict: SAFE TO UPGRADE

…with one mandatory condition and a short list of decisions. Of the 14
high/medium risks, **13 were refuted at source level** (the contract in
question is byte-identical or cosmetically refactored between the tags) and
**1 is real but procedural**:

**R04 (real): three new Alembic migrations, effectively forward-only.**
`1ce6ade7d93b` (group_member index, idempotent), `d4c1a8e37b62` (chat
`timer_at` column + 5 indexes, additive), `6d09d1bf1f23` (repairs
double-encoded OAuth identity rows; its downgrade is a no-op). They chain from
`f0bd01a18a3d` — exactly our live head. Once any of them runs, the old image
refuses to boot, so **the pre-upgrade `backup/backup.sh` archive is the only
rollback path**. The OAuth repair is a verified no-op on our data (all 71
OAuth rows are proper json objects; zero double-encoded rows among 85 users).

This release also FIXES things broken or latent in our v0.11.0: knowledge
search results silently dropped by ACL handling in group-shared collections
(exactly our rag-<slug> setup), notes losing pending saves (our QueuePool
incident class), the DB-connection-holding file-processing watch, and filter
failures now logged with tracebacks instead of debug-swallowed — our six
filters become MORE observable, not less.

## Decisions and do-nots for the upgrade day

- **Do not set** `ENABLE_KNOWLEDGE_FILE_RETENTION` (keeps file/remove deleting
  the file, which rag-admin and load-knowledge assume).
- **Do not enable** `ENABLE_VALVE_ENCRYPTION` (the only path where new valves
  codec code executes; our valves are plain JSON rows).
- **Do not add** a `prefix_id` to the gateway connection — v0.11.1 renders
  connection prefixes in model display names; adding one re-breaks pinned
  chats exactly like the 2026-08-20 id-prefix rollout did.
- **Decide the embedded-page form posture**: v0.11.1 flips the default so
  model-generated HTML previews MAY submit forms. The old blocked behavior can
  be pinned org-wide via the new `ui.default_interface_settings`
  PersistentConfig row — if pinned, that row becomes a fourth reconciler-owned
  surface (document it in the aimo CLAUDE.md).
- **Cosmetic wrinkle to expect (R12)**: v0.11.1 now toasts a processing-failure
  notice naming the raw TypeError for a Strict-OOXML upload that the
  spreadsheet fallback then silently recovers, and the recovered row keeps
  `status:'failed'` + the error string. Optional later patch: have the filter
  clear those two fields when it recovers content.
- **No-Redis notes**: aimo runs without Redis, so (a) the new password-change
  session revocation logs a warning and revokes nothing — moot, sign-in is
  Entra-only with the login form off; (b) the resume-in-progress-reply-on-
  refresh feature does not apply (single replica; no functional regression).
- **Breaking changes that verifiably do not apply here**: THREAD_POOL_SIZE
  (unset), ENABLE_REALTIME_CHAT_SAVE (unset — and now a no-op upstream), the
  image dropping pytest/docker-SDK/netcat (nothing of ours uses them in-pod),
  the async-DNS default flip (in-cluster DNS works with the system resolver).
